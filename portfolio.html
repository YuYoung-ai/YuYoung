Core Strengths

🩺의료기기 현장 CS 실무

설치·A/S·정기점검·병원 응대까지 현장 전 과정을 직접 수행. 장비 증상별 대응, 병원별 이력, 소모품(노즐 등) 관리 등 도메인 지식을 도구 설계에 그대로 녹였습니다.

🛠️현장 문제의 도구화

수기 기록·중복 입력·구두 인수인계 같은 현장 비효율을 직접 웹앱으로 대체. "쓰는 사람이 곧 만든 사람"이라 현장에 붙는 도구를 만듭니다.

💻풀스택 구현력

🔐운영·보안 감각

서명 토큰 인증, 콜드스타트 제거를 위한 런타임 이전, keep-warm, 시크릿 자가 프로비저닝 등 "만드는 것"을 넘어 "안정적으로 굴러가게" 만드는 운영을 챙깁니다.

PROJECT 01 · CORE
📤

현장 처리완료 · 공유

handover
Web · PWA · 핵심 허브
◆ 현장 문제

현장 처리 내역을 카톡·수기로 공유하다 보니 누락·재입력이 잦고, 병원별 처리 이력이 개인에게 흩어져 축적되지 않았습니다.

◆ 직접 구축

처리 내역 작성부터 공유까지 원스톱으로 처리하는 중심 허브. 병원 정보 DB·이슈 이력·재고·주간보고·라벨 기능을 하나의 백엔드(handover_gas Core)로 통합해, 여러 도구가 같은 데이터를 공유하도록 설계했습니다.

◆ 사용 기술
Google Apps Script (통합 백엔드) Google Sheets DB 서명 토큰 검증 조각 캐시 Vanilla JS · PWA
◆ 효과

데이터 단일화로 재입력·누락 제거, 병원별 처리 이력이 자동 축적되어 재방문·인수인계 시 즉시 참조 가능.

PROJECT 02
🏥

병원 데이터 센터

hospital-pc
Web · PC 대화면
◆ 현장 문제

담당 병원의 위치·방문 일정·최근 처리 현황이 여러 곳에 흩어져, 동선 계획과 현황 파악에 시간이 들었습니다.

◆ 직접 구축

지도 기반의 병원 통합 조회 화면. 조회 · 현장 일정 · 대시보드 · 최근 처리의 4개 탭으로 구성하고, 점검 이력·병원 상세를 모달로 즉시 확인. PC 대화면에 맞춰 정보 밀도를 최적화했습니다.

◆ 사용 기술
Kakao Maps SDK 커스텀 오버레이 · 인포윈도우 탭 UI · 모달 반응형 레이아웃
◆ 효과

병원 위치·일정·이력을 한 화면에서 파악해 방문 동선과 일정 계획을 최적화.

PROJECT 03
📊

현장 처리 대시보드

dashboard-pc
Web · 보고 자동화
◆ 현장 문제

주간·월간 업무보고를 매번 손으로 집계·작성하느라 반복 시간이 컸고, 담당자마다 형식이 제각각이었습니다.

◆ 직접 구축

KPI·월별/주차별 추이·노즐 재사용 현황·사용자 숙련도 지표를 필터(슬라이서)로 탐색하는 대시보드. 나아가 주간·월간 보고 PPT를 버튼 한 번으로 자동 생성하고, 생성 전 슬라이드를 미리보기로 확인하도록 만들었습니다.

◆ 사용 기술
PptxGenJS (PPT 자동 생성) 데이터 집계 · 지표화 필터 · 슬라이서 차트 시각화
◆ 효과

반복적인 보고서 작성 시간을 크게 단축하고 보고 형식을 표준화 (예: 주 ○시간 → ○분).

PROJECT 04
📝

A/S 점검 내역서

inspection
Web · 모바일 현장용
◆ 현장 문제

종이 점검 내역서는 사진·서명 첨부와 전달이 번거롭고, 현장에서 작성 후 사무실에서 다시 옮겨 적는 이중 작업이 발생했습니다.

◆ 직접 구축

접수 → 점검 항목 → 조치 → 현장 사진 → 서명으로 이어지는 단계별 입력 폼. 가로 전체화면 손서명 패드, 현장 사진 첨부, 병원 선택 시 최근 방문 이력 자동 조회, 수기 작성용 빈 양식 PDF까지 포함. 완성본은 화면에서 바로 PDF로 렌더됩니다.

◆ 사용 기술
Canvas 손서명 html2canvas (PDF 렌더) 사진 첨부 단계형 폼 UX A/S 코드 마스터 공유
◆ 효과

현장에서 즉시 내역서를 완성·전달해 종이와 재작성 이중 작업을 제거.

PROJECT 05
📖

CUREJET 현장 대응 가이드

guide
Web · 지식 표준화
◆ 현장 문제

장비(CUREJET) 증상별 대응 노하우가 개인 경험에만 흩어져 있어, 신규 담당자와 숙련자 간 대응 편차가 컸습니다.

◆ 직접 구축

증상별 현장 대응법을 빠르게 찾는 가이드. 관리자 모드(비밀번호)에서 증상을 추가·편집·삭제할 수 있는 경량 편집형 구조로 만들어, 현장에서 쌓인 노하우를 계속 반영·공유하도록 했습니다.

◆ 사용 기술
관리자 편집형 구조 (경량 CMS) 비밀번호 보호 단일 파일 경량 앱
◆ 효과

대응 지식을 표준화·공유해 신규 담당자 온보딩과 현장 대응 품질을 균일화.

System & Operations

공통 아키텍처 & 운영

도구를 만드는 데서 그치지 않고, 현장에서 안정적으로 돌아가게 만드는 데 집중했습니다. 아래는 개별 앱을 넘어선 시스템·운영 차원의 고민입니다.

인증 · 데이터 흐름

브라우저 (현장 도구)
handover · inspection · dashboard · hospital · guide
│ ① 로그인 / 검증 ▼
인증 서버 — Deno Deploy
엣지 상시 실행 · 콜드스타트 없음 · HMAC-SHA256 서명 토큰 발급
│ ② 데이터 요청 (토큰 동봉) ▼
데이터 백엔드 — Google Apps Script
토큰을 로컬 HMAC 검증 (인증 서버 왕복 없음) · Google Sheets 운영 DB

📴PWA · 오프라인 대응

Service Worker 캐시와 매니페스트로 설치형 앱처럼 동작. 병원 지하·전파 취약 등 현장 네트워크 환경을 고려했습니다.

🚀콜드스타트 근본 해결

"첫 로그인 30~50초" 문제를 인증 발급기만 GAS→Deno Deploy로 이전해 해결. 토큰 형식이 동일해 데이터 백엔드·프런트를 한 줄도 바꾸지 않고 전환했고, 문제 시 무중단 롤백이 가능합니다.

🔑서명 토큰 · 로컬 검증

데이터 백엔드가 토큰을 스스로 검증하도록 재설계해, 인증 서버로의 검증 왕복을 없애 응답 속도를 개선했습니다.

⚙️운영 자동화

keep-warm 예열, 시크릿 자가 프로비저닝(수동 복붙 제거), epoch 증가로 전원 강제 로그아웃, 선택적 기기 기억 등 운영 편의를 함께 설계했습니다.
