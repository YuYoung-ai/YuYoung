# 유형별 참고 예시 사진·영상

이 폴더에는 실제 처리 이력이 아니라, VOC 유형의 증상과 처리 결과를 설명하는 공개 가능한 표준 예시만 저장합니다.

## 파일 원칙

- 사진은 WebP 권장, 가로 최대 1200px, 장당 100~300KB를 목표로 합니다.
- 영상은 MP4(H.264/AVC), 15초 이하, 5MB 이하만 허용합니다. 자동재생하지 않고 기본 음소거로 표시합니다.
- 환자·직원 얼굴, 병원명, 장비 S/N, 문서·모니터 개인정보, GPS/EXIF 메타데이터가 없어야 합니다.
- 기존 파일을 덮어쓰지 않고 내용 해시가 포함된 새 파일명으로 추가합니다.
- 자료 경로는 반드시 `assets/type-examples/` 아래의 상대 경로만 사용합니다.

## 등록 절차 (권장 · 대시보드 관리 화면)

사진 변환, 영상 제한 검증, 파일명·경로·매니페스트 갱신을 브라우저가 전부 처리합니다.
`대분류|유형` 키나 폴더 슬러그, 해시 파일명을 직접 입력할 일이 없습니다.

1. **관리 화면 열기** — `dashboard-pc.html` 상단의 **🖼 예시자료 관리** 버튼.
   이 버튼을 누른 순간에만 `js/type-example-manager.js` 를 내려받습니다(일반 대시보드 사용에는 포함되지 않습니다).
2. **유형 선택** — 대분류 필터·유형 검색·"미등록만 보기"로 찾은 뒤 행을 펼칩니다.
   목록은 대시보드가 이미 받아 둔 데이터와 이 `index.json` 을 합쳐 만들며, 서버를 다시 호출하지 않습니다.
3. **예시 등록** — 증상/처리 결과 칸에 사진 또는 MP4를 끌어다 놓거나 선택하고 설명을 입력합니다.
   - 사진 1장 또는 영상 1개: **사진·영상 1개**를 선택합니다.
   - 사진 2~4장: **▦ 사진 2~4장 합성**을 선택합니다. 2장은 좌우, 3장은 왼쪽 큰 사진+오른쪽 2장,
     4장은 2×2로 배치되고 순서 번호가 붙은 4:3 WebP 한 장으로 생성됩니다.
   - 합성 미리보기에서 사진을 드래그해 프레이밍 위치를 조정할 수 있고, 확대·90도 회전·초기화를 지원합니다.
     아래 사진 목록은 드래그하거나 좌우 화살표로 순서를 바꿀 수 있습니다. 모바일에서는 방향 버튼으로 위치를 미세 조정합니다.
     조정이 필요 없으면 자동 배치 상태에서 바로 **이 배치로 합성**을 누릅니다.
   - 합성은 브라우저 Canvas 안에서만 처리하며 원본을 GAS·Drive·외부 서버로 전송하지 않습니다.
4. **변환·검증 확인**
   - 사진: WebP(긴 변 최대 1200px, 확대 없음)로 변환하며 EXIF 등 메타데이터를 제거합니다.
   - 영상: 브라우저에서 재생 가능한 MP4인지 확인하고 15초·5MB 제한을 강제합니다. 영상은 재인코딩하지 않습니다.
   원본·결과 크기, 해상도·재생시간과 저장 경로가 화면에 표시됩니다.
5. **저장 · 게시** — 아래 셋 중 하나를 고릅니다. 어느 쪽이든 저장 버튼을 누르기 전에는 어떤 파일도 기록되지 않습니다.
   - **🚀 바로 게시**(권장 · 기기를 가리지 않음): 변환한 파일과 `index.json` 을 저장소에 **커밋 하나로** 올립니다.
     휴대폰·태블릿에서도 그대로 끝낼 수 있고, GitHub Pages 배포가 이어져 **약 1분 뒤 모든 사용자 화면에 반영**됩니다.
     6번(커밋) 단계가 필요 없습니다. 인증 서버에 `GITHUB_TOKEN` 이 설정돼 있어야 버튼이 동작합니다 → `deno-auth/README.md` 13절.
     서버가 Lv.3 권한·파일 경로·내용 해시·매니페스트를 다시 검증하며, 실패하면 아무것도 커밋되지 않습니다.
   - **📁 저장소 폴더에 저장**(Chrome·Edge): 이 저장소의 최상위 폴더를 선택합니다.
     사진은 `assets/type-examples/media/<해시 12자리>.webp`, 영상은 `<해시 12자리>.mp4`로 저장되며 `index.json` 은 마지막에 기록됩니다.
     한 번 고른 폴더는 브라우저에 기억해 **다음 저장부터는 선택 단계를 건너뜁니다**. 다른 폴더로 바꾸려면 **📂 폴더 변경**을 누릅니다.
   - **⬇ 파일 다운로드**: 그 밖의 브라우저용 폴백. 받은 파일을 화면에 안내된 저장소 경로에 그대로 넣습니다.
6. **커밋**(폴더 저장·파일 다운로드로 저장했을 때만) — 저장이 끝나면 붙여 넣을 커밋 명령이 화면에 표시되고
   **📋 커밋 명령 복사**로 그대로 복사할 수 있습니다. `git status` 로 변경 파일을 확인한 뒤 커밋·푸시합니다.
   교체 후 참조되지 않는 옛 파일은 "정리 후보"로만 안내합니다. 필요할 때 직접 지우세요(도구는 자동 삭제하지 않습니다).

## 게시 경로 (🚀 바로 게시)

```
관리 화면 → (Lv.3 토큰) → 인증 서버 → GitHub 커밋 1개 → Pages 자동 배포(약 1분)
```

- GitHub 쓰기 토큰은 인증 서버(Deno) 환경변수에만 있습니다. 공개 페이지에는 어떤 토큰도 들어 있지 않습니다.
- 파일을 한 개씩 올린 뒤 마지막에 `index.json` 을 커밋합니다. 중간에 끊기면 저장소는 그대로 남습니다.
- 파일명이 내용 해시라서 같은 자료를 다시 올려도 파일이 늘지 않고, 같은 내용이면 빈 커밋도 만들지 않습니다.
- 잘못 올린 게시는 해당 커밋 하나만 되돌리면 파일과 매니페스트가 함께 원복됩니다.

## 대시보드 출력

- 처리 이력에서 VOC 유형 필터를 선택하면 해당 유형의 증상·처리 결과 미리보기가 자동으로 표시됩니다.
- 처리 이력 행을 직접 선택해도 같은 예시자료 영역이 해당 유형으로 전환됩니다.
- 사진·영상 미리보기를 누르면 절감액 산정 근거자료와 같은 공통 전체화면 뷰어가 열립니다.
- 사진은 전체화면 확대, 영상은 사용자 조작·기본 음소거로 재생되며 이전·다음과 원본 열기를 지원합니다.

## 등록 절차 (비상용 · 수동)

관리 화면을 쓸 수 없을 때만 사용합니다.

1. 사진은 WebP(긴 변 1200px 이하, 100~300KB)로 변환합니다. 영상은 MP4(H.264/AVC)·15초·5MB 이하인지 확인합니다.
2. `assets/type-examples/media/` 아래에 내용을 알아볼 수 있는 파일명으로 넣습니다(기존 폴더에 넣어도 됩니다).
3. 아래 형식대로 `index.json` 의 `items` 에 항목을 추가하고 `updatedAt` 을 그날 날짜로 바꿉니다.
4. 유형 키는 대시보드 데이터의 `대분류|유형` 과 같아야 합니다.
   공백만 다른 표기(`노즐 누수(약액유입)` / `노즐 누수(약액 유입)`)는 **키를 새로 만들지 말고 기존 키를 그대로 씁니다**
   — 대시보드는 공백을 무시한 비교로 두 표기를 같은 예시에 연결합니다.

## 매니페스트 형식

```json
{
  "schema": 1,
  "updatedAt": "2026-08-16",
  "items": {
    "장비|노즐 누수": {
      "symptom": {
        "src": "assets/type-examples/nozzle-leak/symptom-a82f019c.webp",
        "text": "노즐 주변에 약액이 맺히거나 누수가 확인됩니다."
      },
      "after": {
        "src": "assets/type-examples/media/0123456789ab.mp4",
        "text": "실링 교체와 내부 세척 후 누수가 없는 상태입니다.",
        "kind": "video",
        "bytes": 1843200,
        "duration": 8.4
      }
    }
  }
}
```

유형 키는 대시보드 데이터의 `대분류|유형`과 정확히 일치해야 합니다.

## 캐시 정책

- `index.json` 은 서비스워커에서 네트워크 우선입니다 — 갱신하면 바로 반영됩니다.
- `assets/type-examples/media/<해시>.webp` 만 캐시 우선입니다. 내용이 바뀌면 파일명이 바뀌므로 옛 사진이 남지 않고,
  첫 요청 이후에는 오프라인에서도 그대로 표시됩니다.
- MP4는 사용자 재생 시에만 요청하며 서비스워커 CacheStorage에는 저장하지 않습니다.
- 대표 사진·영상은 프리캐시(`sw.js` 의 `ASSETS`)에 넣지 않습니다. 배포 때마다 전 사용자가 전량 재다운로드하게 됩니다.
