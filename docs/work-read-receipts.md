# 처리 내역의 알림 읽음 현황 (웹 v260)

처리 내역의 최근 기록 오른쪽 **읽음 현황**을 누르면 알림별 수신 계정의 읽음·미확인 상태와 최초 읽음 처리 시각을 확인한다. 접수 상세에서도 같은 기능을 사용한다. 모바일에서는 카드 하단 오른쪽의 작은 글자 버튼을 사용한다. 버튼 문구는 짧게 유지하고, 최근 알림의 읽음·미확인 수는 툴팁과 접근성 이름에 표시한다. 전체 목록의 모든 접수마다 조회하지 않고 사용자가 연 접수만 조회한다.

- 최근 알림이 기본으로 선택되며, 배정·방문 일정·상태 변경·AS 처리 현황·AS/점검 내역서 알림을 선택해서 비교한다.
- 연결된 AS 처리 현황은 실제 접수의 결과 기록 ID로 찾는다. 병원명이 같다는 이유로 다른 접수의 알림을 포함하지 않는다.
- 새로고침은 선택한 알림의 최신 상태를 다시 조회한다. 창을 다시 열면 최신 알림으로 돌아간다.
- 기존 `notification_read`와 `notification_mark_read`의 동일한 기록을 읽는다. 선택 읽음·모두 읽음도 읽음에 포함한다. 실제 본문을 끝까지 읽었다는 증명이나 업무 완료·결과 검토 여부를 뜻하지 않는다.
- 읽음 현황 창과 일반 접수 상세 조회는 알림을 읽음으로 변경하지 않는다. 기존 알림 클릭 경로의 읽음 처리는 그대로 유지한다.
- 수신 계정 기준이다. 동일인이 Google 계정 두 개를 사용하면 각각 표시된다. 같은 이름의 계정은 중복 계정 안내를 표시한다. 기기 구독 여부와 무관하게 실제 알림함에 등록된 수신 계정을 집계한다. 휴대폰에 푸시가 전달됐다는 확인은 아니다.
- 발송 당시의 수신 계정 이름을 30일 동안 함께 저장한다. 기존 알림은 현재 계정 목록의 이름으로 보완하고, 확인할 수 없으면 `이전 수신 계정`으로 표시한다. 계정 삭제·배정 변경·수신 설정 변경으로 과거 수신자를 새로 계산하지 않는다.
- 기존 알림과 동일하게 생성 후 30일 동안 보관하며, 읽음 시각은 한국 시간으로 표시한다. 보관 기간이 지난 알림이나 알림을 만들지 않은 과거 가져오기 기록에는 현황이 없다.

## API와 권한

`notification_receipts`에 `requestId`와 선택적인 `notificationId`를 전달한다. Google 계정 인증과 기존 업무 조회 접근 기준을 적용한다. 해당 접수에 연결된 이벤트만 선택할 수 있다. 계정 UID·이메일·기기 정보는 응답에 포함하지 않는다. 영구 삭제된 접수는 조회할 수 없다.

신규 알림에는 `recipientName` 스냅샷만 추가하며 기존 읽음 기록을 변경하거나 이전 알림을 재발송하지 않는다. 이벤트의 원래 만료 시점을 유지하고 접수 영구 삭제 시 새 이름 스냅샷도 정리한다. 발송 대상 등록이 진행 중이면 부분 집계임을 표시한다. 1,000개 초과 이벤트·수신자는 잘못된 부분 합계를 표시하는 대신 조회 오류를 반환한다.

## 검증과 배포

`deno task test:read-receipts`는 격리된 실제 KV에서 대상·읽음 시각·일괄 읽음·권한·접수/원본 격리·이름 보존·계정 변경·30일 보관을 검증한다. `node test/browser/work-read-receipts.cjs`는 Playwright와 Edge에서 모바일/PC UI, 알림 선택, 실패/재시도, 로그아웃 중 응답, 실제 처리내역 및 상세 연결, 댓글 초안 보존을 검사한다. `PLAYWRIGHT_MODULE`로 기존 설치 모듈 경로를 지정할 수 있다.

운영 반영 시 **Deno 서버를 먼저 갱신**해 `notification_receipts` API를 준비한 뒤 정적 웹 v259을 배포한다. 기존 API·로그인·KV·푸시 키는 유지한다. 운영 접수나 사용자 계정으로 시험 기록·푸시를 만들지 않는다.

2026-10-19 운영 반영 준비: 최신 main의 교체품·재고 연동 변경을 통합하고, 기존 운영 v258과 구별되도록 웹 캐시 v259 및 Deno `deno-1.11.1-notification-receipts`를 사용한다.

2026-10-19 웹 v260: 읽음 현황 진입점을 최근 기록 우측으로 옮기고 배경·테두리 강조를 제거했다. 서버 `deno-1.12.0-notification-reminders`와 함께 배포한다.


## 미확인 대상 재알림 (v260)

미확인 계정 옆의 **재알림**은 선택한 기존 알림을 해당 계정의 연결 기기에만 다시 푸시하도록 요청한다. 알림함 항목을 새로 만들거나 읽음·업무 상태를 변경하지 않는다. 발송 대기열 등록과 실제 기기 수신을 구분해 표시한다.

- `notification_remind`는 같은 업무 조회 권한으로 접수·이벤트·수신 계정을 다시 검증한다. 계정 UID 대신 이벤트별 불투명 식별자를 사용한다.
- 계정·알림 기기·현재 수신 설정이 유효하고 해당 알림이 아직 현재 배정/일정에 맞는 경우만 가능하다. 이미 확인한 계정과 지난 배정 알림은 제외한다.
- 같은 알림·계정에는 10분 간격을 적용하며 동시 요청도 원자적으로 중복 차단한다. 요청 시간과 요청 계정은 기존 30일 보관 범위 안에서 저장한다.
- 기존 발송 대기열을 사용한다. 발송 전에 읽음, 계정·기기 연결, 설정, 현재 업무 내용을 다시 확인하며 일시적 실패는 기존 재시도 정책을 따른다. 읽음 처리된 뒤 대기 중이던 재알림은 발송하지 않는다.
- 최초 발송 후 24시간이 지났어도 보관 기간 내 유효한 알림은 재요청 가능하며, 재알림 자체의 최대 발송 대기는 24시간이다.
- 실제 운영 사용자에게 시험 재알림을 보내지 않는다. `deno task test:reminders`는 격리 KV와 모의 푸시로 검증한다.
