# 접수 → 현장 기록 → 내역서

처리 내역의 접수를 열면 다음 동작을 표시한다. 연결된 Handover 기록이 없으면 **현장 기록 작성**, 기록이 있으면 **내역서 작성**, PDF가 있으면 **내역서 확인**이다. 연결 기록이 여러 개면 실제 처리일과 S/N을 보고 사용할 기록을 선택한다.

## 연결 원칙

- 주소에는 접수 ID와 원본 기록 ID만 전달한다. 병원명과 증상은 인증 후 서버에서 읽는다.
- 현장 기록 작성 시 접수의 병원·배정자·방문 예정일을 입력한다. 작업자는 실제 처리일과 장비를 확인한다. 여러 S/N 중 첫 장비를 임의로 선택하지 않는다.
- 접수 증상은 참고 정보로 보여준다. 처리 내용이나 처리 결과로 자동 저장하지 않는다.
- 기존 현장 기록 초안이 있으면 별도로 보관하고 선택해서 이어 쓸 수 있다.
- 시트 저장 응답에서 확인된 고정 원본 ID를 접수에 연결한다. 응답이 불분명하면 원래 저장 ID로 확인한다. 접수 연결 실패 시 같은 연결 작업을 재시도하며 Handover 행을 다시 생성하지 않는다.
- 접수의 등록일·방문일·영업 담당자·증상은 현장 기록 연결로 덮어쓰지 않는다. 완료·보류·취소 상태와 기존 완료 정보·보완 메모를 유지한다.

## 내역서 작성과 저장

내역서는 최신 Handover의 병원·S/N·처리일·처리 내용과 접수의 등록일·영업 담당자를 구분해서 불러온다. 동일 원본의 작성 중인 내역서가 있으면 기존 내용·사진·서명을 유지한다. 저장 공간이 부족하면 사진을 삭제해서 저장 성공으로 표시하지 않으며 화면 이동을 중단한다.

PDF 생성 결과는 **PDF 생성 / Drive 저장 / Handover 연결 / 댓글 첨부** 네 단계로 표시한다. 파일은 최대 7MiB이며 Google Apps Script를 통해 Google Drive로 전송한다. Deno에는 원본 연결과 파일 메타데이터만 전달한다. 기존 Apps Script v83으로 동작하므로 이번 단계에는 GAS 배포나 시트 열 변경이 필요 없다.

파일 저장이 완료되면 내역서 링크를 즉시 보여준다. 댓글 확인이 실패하면 **댓글 연결 다시 시도**로 원본 갱신과 첨부 확인만 수행한다. PDF 바이트를 다시 업로드하지 않는다. 다른 PDF가 최신 문서가 되었거나 댓글이 삭제된 경우에는 접수에서 확인하도록 안내한다.

응답 유실로 업로드를 재시도할 때 원래 파일·업로드 ID·SHA-256·문서 버전을 유지한다. 다른 작업자가 저장한 최신 PDF의 버전을 재시도 기준으로 채택하지 않는다.

## 검증

- `test/work-document-flow.mjs`: 원본 소유권, 같은 병원·날짜의 복수 접수, 상태/메모/완료 정보 유지, 최신 파일·댓글 확인, 여러 S/N, 전체 처리 내용, 저장 공간 부족 시 초안 보존.
- `test/handover-workflow.mjs`: 확인된 원본 ID, 새로고침 후 같은 연결 작업 재시도, 확인되지 않은 저장의 원래 ID 복구, 초안의 인증 토큰 제외.
- `test/inspection-upload.mjs`: 7MiB 전송, Google 전용 파일 경로, 댓글 연결만 재시도, 업로드 재시도 충돌, 로그인 계정 변경 차단.
- Chrome 격리 미리보기: 접수 선택 → 현장 기록 저장 → 접수 연결 → 실제 PDF 생성 → 모의 파일 저장 및 댓글 확인. 운영 업무 데이터와 Drive에 시험 기록을 생성하지 않는다.

실제 휴대폰의 카카오톡 파일 선택 및 앱 종료 상태 알림은 해당 기기에서 별도로 검증해야 한다.
