# Handover·내역서 ID 연결 복구

## 수정한 경로

시트 기록 성공과 접수 연결 완료를 별도로 취급한다. 저장이 확인된 기록은 접수 연결 응답을 기다리는 동안에도 내역서로 이어갈 수 있으며, 새 내역서에 기록 ID와 접수 ID를 함께 전달한다. 기존 작성 작업은 보관한다. 저장 결과 불명·저장 중·현재 입력 미기록 상태에서는 이어쓰기를 열지 않는다.

내역서의 병원·처리일·S/N을 바꾸거나 내역서를 복제하면 이전 Handover·접수·PDF 연결을 해제한다. 직접 진입·초안 복원으로 과거 ID가 남아 있어도 Google 저장 서버의 원본 확인 단계에서 다른 병원·날짜·장비의 연결을 거절한다. 생성 시 확인한 동일 PDF는 이후 원본 정정과 관계없이 생성 당시 대상으로 저장·재시도한다.

Safari에서 `crypto.randomUUID`가 없을 때도 `crypto.getRandomValues`로 작업 ID를 생성한다. 중단된 PDF를 복구할 때는 작업 ID 외에도 병원·처리일·S/N을 확인한다.

## 수동 연결

1. Handover 시트 기록이 완료되면 표시된 기록 ID를 확인하고 `기록 ID 복사`를 사용할 수 있다. 시트의 ID 열을 직접 바꾸지 않는다.
2. 내역서 상단 `Handover 기록 연결 변경`을 연다.
3. `현재 병원의 기록 찾기`에서 처리일·S/N·처리 내용을 확인해 선택하거나, 복사한 ID를 입력하고 `입력한 기록 조회`를 누른다.
4. 접수까지 직접 지정할 때는 접수 ID 또는 `?request=...`가 포함된 주소를 입력한다. 미지정 시 해당 원본의 현재 접수 연결을 확인한다. 접수 관리의 기존 Handover 연결 관리에서도 원본을 선택할 수 있다.
5. 원본 미리보기를 확인하고 `확인한 기록으로 연결`을 누른다. 다른 병원·처리일·S/N은 연결할 수 없다. 연결 요청 응답이 유실되면 같은 작업 ID로 재시도한다.
6. 같은 Handover 기록의 기존 PDF는 `저장·댓글 연결 확인`으로 첨부만 재확인한다. 다른 Handover 기록을 선택했다면 현재 내용으로 PDF를 새로 생성한다. 이전 기록의 PDF를 다른 기록으로 조용히 옮기지 않는다.

## 삭제 후 재등록한 접수

운영 Workers 패치는 원본의 현재 접수 연결을 기준으로 문서의 과거 접수 연결을 보정한다. 과거 접수가 실제로 삭제되어 있고, 새 연결의 병원·처리일·S/N이 기존 문서와 일치하는 경우에만 적용한다. 원본 처리 결과·삭제된 접수의 이력·기존 PDF 파일은 보존하며 새 접수에는 자동 댓글 하나만 만든다. 다른 활성 접수 또는 소유 접수 데이터가 누락된 문서는 강제로 가져오지 않는다. 사용자가 삭제한 현재 접수의 댓글도 자동 복원하지 않는다.

## 배포 단위

운영 화면과 운영 Workers 소스는 별도로 관리되고 있다. 이 PR의 프런트와 GAS 변경에 더해 실제 운영 Workers 소스 기준 `docs/patches/handover-document-rebind.patch`를 함께 반영해야 한다. 이 패치를 공개 저장소의 구형 Deno 모듈에 억지로 적용하지 않는다. 패키지의 `backend-baseline.json` 해시와 패치 적용 전 운영 소스를 대조한다.

- Apps Script: 기존 Handover 프로젝트의 `handover_inspection_pdf_gas.gs`를 갱신하고 기존 웹앱 배포를 새 버전으로 갱신한다. 웹앱 URL과 기존 인증 설정을 유지한다.
- Workers: 실제 운영 소스에 패치를 적용하고 아래 D1 검증·빌드를 수행한 뒤 기존 운영 Worker에 배포한다. DB 마이그레이션이나 데이터 초기화는 필요하지 않다.
- Pages: 프런트 파일과 서비스워커 v282를 배포한다. 기존 초안·전송 보관함은 유지한다.

## 검증과 확인 범위

`node test/inspection-upload-gas.mjs`는 ID가 있는 경우에도 병원·처리일·S/N 불일치를 거절하고, 생성 후 원본이 정정되어도 고정된 PDF 재시도와 파일 무결성·버전 검사를 유지하는지 확인한다.

`node test/browser/inspection-relink.mjs`는 Playwright WebKit으로 실제 HTML을 390×844에서 실행한다. API·인증·병원·PDF 데이터는 합성값으로 대체하며 운영 데이터에 쓰지 않는다. Playwright를 설치하거나 `CODEX_PRIMARY_RUNTIME_NODE_MODULES`를 지정하고, 필요한 경우 `PLAYWRIGHT_WEBKIT`으로 실행 파일을 지정한다. `OUTPUT_DIR`로 결과 저장 위치를 지정할 수 있다.

Workers 패치에 포함된 `test/work-document-rebind.mjs`는 D1에서 삭제 후 재등록, 과거 ID의 지연 전달, 동시 재시도·댓글 중복 방지, 활성/누락 소유자 보호와 삭제 댓글 보존을 확인한다. 기존 `test/work-pdf-delivery-retry.mjs`, 문서 흐름과 PDF 첨부 검증도 함께 수행한다.

이 검증은 합성 데이터로 재현한 결과다. 실제 아이폰 실기기, 실제 문제 건의 원본 PDF 내용과 기록 ID, 운영 배포 후 결과는 별도로 확인해야 한다. 이 변경만으로 기존에 잘못 연결된 병원 기록이 자동 정정되었다고 보지 않는다.
