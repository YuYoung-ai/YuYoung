# CS 서비스 접수 수정과 상세 필터

빠른 필터는 전체 → 진행중 → 오늘 방문 → 이번주 → 지난주 → 이번달 → 휴지통 순서다. 전체·기간 조회에는 완료 접수도 포함한다. 진행중에는 엔지니어나 일정이 미배정된 접수도 포함하고 완료·취소·삭제는 제외한다.

이번주·지난주는 근무 달력에서 선택한 날짜를 기준으로 월요일부터 일요일까지 조회한다. 주가 월이나 연도를 걸쳐도 전체 주를 조회한다. 이번달은 근무 달력의 선택 월, 오늘 방문은 한국 시간의 오늘을 기준으로 한다. 상세 필터의 년·월·분기는 방문일에 적용한다. 같은 항목의 복수 선택은 OR, 서로 다른 항목과 빠른 필터는 AND로 적용한다.

상단 수정 버튼을 누르면 기존 목록과 업무 상세의 값을 더블클릭해 그 자리에서 바꾼다. 연필 아이콘은 표시하지 않으며, 키보드로 선택한 값은 Enter 또는 F2로 수정한다. ✓는 입력 적용이며 서버 저장이 아니다. 접수 저장으로 해당 접수의 변경만 서버에 저장한다. 초안은 PC에 보존하고 동시 수정은 revision으로 감지한다. 병원을 변경하면 확인 체크가 필요하고 기존 댓글·처리 결과는 보존한다. 선택한 병원DB의 이름·지역으로 접수의 병원 정보가 바뀐다. 접수의 `sn`과 `hospitalReferenceSN`은 선택한 최신 DB 장비 번호를 반영한다. 기존 처리 결과의 원본 장비 번호와 수정 전 감사 이력은 보존한다. 저장 후 보관된 Handover로 연결 조건을 재검사한다.

병원·장비 정보, 영업 담당자, AS·N-CARE 후보는 병원정보DB만 사용한다. Flow 이전 병원과 처리 이력은 등록 후보에 추가하지 않는다. 병원DB에는 엔지니어·CS 접수 담당 열이 없으므로 엔지니어는 기존 Handover 담당자 마스터, CS는 직접 입력과 로그인 이름을 사용한다. 상세 필터의 CS 이름은 조회를 위한 접수 담당 값이며 신규 등록 자동완성에는 사용하지 않는다. 상태·A/S·점검은 업무의 고정 구분이다.

AS 유·무상과 N-CARE 수정은 `serviceOverrides`로 해당 접수에만 보관한다. ‘병원DB 값 사용’을 선택해 저장하면 접수 수정값을 해제한다. 수정값이 없는 접수는 동기화한 병원DB 값을 표시한다. 병원 키가 달라졌다면 정확히 같은 병원명·지역의 유일한 현재 DB 행을 연결한다. 같은 병원명·지역에 여러 장비가 있으면 개별 S/N으로 구별하며 모호하면 직접 선택한다. 이름이 변경된 경우에는 기존의 유일한 정확한 S/N 일치도 사용한다. 유사 이름은 추정하지 않는다.

다른 PC의 변경은 기존 동기화 버튼으로 KV에서 가져온다. 병원DB 최신 원본을 바로 반영하려면 상세 필터 또는 접수 등록의 ‘병원DB 새로고침’을 사용한다. 이 명시적 동작만 기존 인증된 GAS `hospdbrich` 조회를 수행하며 성공하면 KV 기준 정보를 교체한다. 기존 5분 GAS 작업도 기준 정보의 변경을 전달한다. 접속 시 자동 동기화 정책과 Handover 원본은 변경하지 않는다.

검증: `node test/work-fields.cjs`, `node test/work-ui-cache.mjs`, `node test/work-kv.mjs`, `node test/work-bridge.mjs`. 실제 HTML·CSS·JS와 격리된 메모리 서버로 완료 접수 병원명 변경, 열린 상세 갱신, 접수별 서비스 조건, 달력 주간 범위, 390px 휴대폰 수동 시간 저장도 확인했다.

병원 조회 PC 화면의 왼쪽 ‘접수 등록’은 지도와 소요시간을 유지한 채 오른쪽 접수 패널을 연다. 선택한 병원명·장비 번호·지역이 병원정보DB의 유일한 항목과 정확히 일치할 때만 자동 선택한다. 일치하지 않거나 여러 후보가 있으면 양식에서 DB 병원을 직접 선택한다. 접수 패널의 초안은 기존 CS 화면 초안과 별도로 이 PC에 보관하고, 저장 성공 후 패널을 닫는다.

Handover 저장은 내구성 있는 대기열에 먼저 기록하고 대기 집계를 즉시 KV에 전달한다. 결과 전송은 기존 약 5분 작업을 사용한다. 동일 기록을 다시 수정해도 대기 건수는 한 건이며 전송 이벤트 수는 별도다. 집계 전달 실패는 원본 저장을 실패로 바꾸지 않으며 다음 작업에서 재시도한다. CS 화면은 동기화 버튼을 눌러 서버의 최신 집계를 확인한다.

추가 검증: `node test/work-launch.cjs`, `node test/work-queue-save.mjs`, `node test/work-queue.mjs`. 실제 GAS 저장 훅·대기열·Deno 메모리 KV·화면 배지로 즉시 집계, 재수정, 일부 실패, 추가 저장 시 오류 보존, 재시도, 20건 배치 잔여를 가상 검증했다. 운영에 테스트 접수를 만들지 않았다.
