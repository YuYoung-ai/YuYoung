# 업무 알림 확장 (웹 v251 / Deno 1.11.0)

화면·푸시 명칭은 **AS 처리 현황**, **AS/점검 내역서**로 표시한다. 내부 `handover`, `pdf` 식별자와 기존 시트명은 유지한다.

| 발생 조건 | 수신 대상 |
|---|---|
| 접수 생성·담당자 변경 | 배정 담당자 + 관리자. 미지정 접수는 기존처럼 전체 |
| 방문 일정 등록·변경 | 배정 담당자 + 관리자 |
| 실제 업무 상태 변경 | 배정 담당자 + 관리자. 완료 상태로 바뀌어도 발송 |
| AS 처리 현황 최초 저장 완료 | 로그인한 원본 작성자 + 관리자 |
| AS/점검 내역서 저장 후 접수 댓글 연결 완료 | 파일 등록자 + 관리자 |
| 당일 휴무·당직 | 한국 시간 08:30, 업무 사용자 전체 중 당일 휴무자 제외 |

관리자는 설치·알림 설정에서 자신의 계정으로 받을 여섯 종류를 각각 선택한다. 초기값은 모두 수신이다. 다른 사용자의 설정이나 업무 확인 상태를 변경하지 않는다. 휴무자 제외는 관리자에게도 적용한다. 기기 푸시는 기존 기기 알림 연결과 OS 권한이 필요하다. 기기가 없어도 로그인 계정의 알림 목록에 기록한다.

## 저장·전송

- 접수 변경과 알림 이벤트·대기열을 한 KV 트랜잭션으로 커밋한다. 동일 작업 재시도는 새 이벤트를 만들지 않는다. 구독 만료, 계정 전환, 재배정, 이미 읽은 알림의 지연 재시도 방지를 유지한다.
- 한 접수에 방문 일정과 상태 등 여러 종류가 발생해도 이벤트별 푸시 태그를 사용한다. 담당자가 미연결이면 관리자에게 전달한 뒤에도 배정 담당자의 연결 복구를 기다린다. 기존 권한 기준 이하 계정은 제외한다.
- AS 처리 현황은 서명된 GAS 브리지/인증된 원본 조회로 받은 `schemaVersion:2`, `originalAuthor`, `createdAt`를 사용한다. 활성화 이전 원본, 예전 이력 가져오기, 재조회, 검수 출판, PDF 업데이트는 작성 완료를 다시 알리지 않는다. 기록 ID별 발송 표시와 원본을 함께 저장한다. 작성자 이름을 기존 업무 소유권 기준인 인증 계정명과 대조한다. 같은 담당자가 Google 계정을 여러 개 사용하면 각 활성 계정의 알림함에 전달하고, 기기 푸시는 현재 연결된 계정의 구독만 사용한다.
- 일반 AS 처리 현황 화면에서도 저장 성공을 확인한 뒤 기존 인증 원본 조회를 비동기로 호출해 알림을 앞당긴다. 실패·화면 종료 시 기존 5분 GAS 대기열이 재전달한다. 저장 성공 상태를 후속 알림 오류로 되돌리지 않는다. 접수에서 열린 작성 화면은 기존 원본 확인·연결 흐름을 사용한다.
- 내역서는 파일 생성/업로드만으로 완료 알림을 만들지 않는다. 기존 `pdf_attachment` 댓글 저장 커밋에서 발생하며, 활성화 이전 파일의 재연결은 조용히 처리한다. 독립 문서는 접수 댓글 연결이 완료될 때 알린다.
- 기존 매분 Deno Cron이 08:30부터 당일 근무 일정을 읽고 날짜별 원자적 표시로 한 번 큐에 넣는다. 장애 시 09:00 전까지 재시도한다. 일정이 없는 날은 보내지 않으며 전날 안내를 뒤늦게 발송하지 않는다. 큐 생성 때와 실제 기기 전송 때 휴무 여부를 확인한다. 08:30 이후 신규 등록/정정된 일정은 상세에서 최신 내용을 보여 주며 별도 두 번째 정기 알림을 만들지 않는다.
- 알림은 기존처럼 30일 보관한다. 사용자·일정·이벤트 본문은 URL에 넣지 않고 식별자만 전달한다. 휴대폰의 절전/네트워크/OS 설정에 따라 실제 표시 시각은 달라질 수 있다.

## 열람과 권한

접수 알림은 기존 최신 원본 조회 → 목록 동기화 → 상세 확인 흐름을 유지한다. 접수에 연결되지 않은 AS 처리 현황과 근무 일정은 `notification.html`에서 본인의 받은 알림 ID를 검증한 뒤 현재 저장된 내용을 읽는다. 다른 계정의 알림 ID는 읽을 수 없다. 상세 조회 성공 뒤에만 알림을 읽음 처리하며 업무 상태/검수 승인은 바꾸지 않는다. 근무 일정은 해당 날짜의 달력으로 바로 연결된다. 로그인 만료 시 알림 주소를 보존하며 토큰과 외부 이동 파라미터는 제거한다.

기존 GAS·Drive 권한이나 데이터베이스를 변경하지 않는다. 최신 원본 저장 메타데이터를 제공하는 기존 GAS 3.9.0 계약을 사용한다.

## 검증

`deno task test:notifications`는 격리된 실제 Deno KV에서 수신자 분기, 완료 상태, 관리자 설정 ACL/수신 해제, 작성자와 배정자 구분, 원본 중복/과거 데이터 제외, 파일·댓글 완료 및 재시도, 한국 시간 경계, 동시 Cron, 휴무 관리자 포함 수신 제외를 검사한다. 기존 접수 KV, 인덱스, Handover 검수/문서 연동, 알림 구독/읽음/재시도, 서비스워커, 인증 복귀, 알림 실행 동선, 근무 일정 및 GAS 저장 성공 검사를 함께 유지한다. 운영 데이터에는 시험 기록이나 시험 푸시를 만들지 않는다.


## Google 전용 계정

로그인 UI와 공통 클라이언트의 비밀번호 인증을 제거한다. 기존 `login` 요청은 `google_login_required`로 거부하며 중앙 인증 서버는 Google 식별자가 없는 이전 세션과 비밀번호로 기억한 기기를 거부한다. 기존 Google 세션과 기기 로그인은 유지한다. 알림 수신 계정·담당자 연결·관리 화면의 활성 기기 목록에는 Google 계정만 포함한다. 가이드와 병원 이력 편집은 별도 비밀번호 없이 현재 Google 계정의 기존 권한을 확인한다. AutoDoc의 이전 비밀번호 화면도 공통 Google 로그인으로 안내한다.

기존 접수, 처리 이력, 알림 및 과거 감사 기록은 삭제하지 않는다. 이전 비밀번호 환경설정은 더 이상 읽거나 인증에 사용하지 않는다. GAS의 기존 HMAC 검증 라이브러리와 배포는 변경하지 않으므로, 직접 GAS를 호출하는 이미 발급된 구형 토큰은 각 토큰의 기존 만료 정책을 따른다. 중앙 서버의 신규 발급·검증·업무 API에서는 즉시 거부한다.
