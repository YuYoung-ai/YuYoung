# 병원 DB 수정과 Handover 연결

## 연결 기준

병원명과 방문 날짜(접수) = 처리 날짜(Handover)를 비교한다. 같은 병원·날짜에 접수와 결과가 각각 한 건이면 S/N이 달라도 결과를 자동 연결한다. 실제 결과의 장비 번호는 Handover 값으로 보존한다. 처리 결과가 없는 원본, 취소·보류·완료·삭제된 자동 연결 대상, 다른 활성 접수에 이미 연결된 결과는 기존 정책대로 제외한다. 자동 연결 후에는 결과확인 상태를 사용한다.

같은 병원·날짜에 접수가 여러 건이면 S/N으로 연결 대상을 구별한다. `BW4015,BV5015`는 두 번호로 비교하며 쉼표·세미콜론·공백·줄바꿈·슬래시를 지원한다. 대소문자와 전각 문자를 정규화하고 번호 전체를 비교한다. `BV501`은 `BV5015`와 일치하지 않는다. 하나의 원본 S/N이 여러 접수에 해당하면 자동 연결하지 않는다.

하나의 접수에 여러 결과를 자동 연결하는 기존 동작은 유지한다. 결과마다 S/N이 있고 서로 겹치지 않아야 한다. 동일 장비의 여러 결과 또는 S/N 미기록은 직접 선택한다.

## DB 수정 후 반영

병원DB 새로고침은 현재 참조 목록을 갱신한다. 기존 접수·결과를 일괄 덮어쓰지 않는다. DB의 S/N이 변경되어 기존 병원 키가 사라졌다면 병원명과 지역이 정확히 같은 유일한 현재 행을 연결한다. 여러 장비 행이나 다른 지역 지점은 사용자가 선택한다.

목록 수정과 상세의 기본 정보 수정 모두 저장 시 선택한 DB의 최신 S/N을 접수 `sn`과 `hospitalReferenceSN`에 반영한다. 같은 병원의 S/N 정정에는 병원 변경 확인을 요구하지 않으며, 댓글이 있다는 이유로 정정을 차단하지 않는다. 다른 병원으로 변경할 때는 기존 확인 절차를 사용한다.

접수 수정 저장 후 해당 접수의 연결 조건을 KV에 보관된 Handover로 다시 검사한다. 저장 응답에 최신 접수·처리 결과·댓글을 포함하므로 화면 갱신을 위한 추가 원본 조회는 필요하지 않다. 동기화 버튼도 보관된 원본의 미연결 접수를 다시 검사한다. 원본이 아직 KV에 전달되지 않았다면 기존 Handover 불러오기 또는 연동 작업으로 원본을 받아야 한다.

이미 저장된 결과 원문·S/N·보완 메모와 수정 전 값의 감사 이력은 보존한다. 원본 재전달과 동일 저장 재시도는 결과를 중복 생성하지 않는다. 자동 연결 재검사가 실패해도 이미 성공한 접수 저장을 실패로 보고하지 않는다.

## 구분

Handover E열의 `점검/AS` 헤더를 읽으며 `점검/A/S`, `구분`도 지원한다. 열 번호를 고정하지 않고 헤더로 읽는다. `AS`, `A/S`, 소문자·주변 공백·전각 표기는 `A/S`로 정규화하고 `점검`은 유지한다. 다른 구분은 결과 연결 대상으로 간주하지 않는다. 연결한 원본의 구분을 접수와 처리 결과에 반영한다.

## 배포와 검증

기존 Deno 앱의 저장소 연결 배포로 `deno-auth/work-store.ts`를 반영한다. Handover Apps Script 프로젝트에서는 `hospital_work_gas.gs`만 교체하고 기존 웹 앱 배포를 새 버전으로 갱신한다. 시트 데이터 초기화, `setupHospitalWork` 또는 KV 이전을 다시 실행할 필요가 없다. 웹 파일은 기존 Pages 배포를 사용하며 서비스 워커 버전은 v218이다.

검증: `node test/work-kv.mjs`, `node test/work-fields.cjs`, `node test/hospital-work.mjs`, `node test/work-ui-cache.mjs`, `node test/work-bridge.mjs`. S/N 불일치·복수 번호·중복 후보·DB 키 변경·두 수정 경로·구분 별칭·저장 후 화면 캐시·중복 저장·원본 및 댓글 보존을 확인한다.
