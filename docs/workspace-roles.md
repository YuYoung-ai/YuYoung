# 역할별 업무 화면과 알림 정리

웹 v246 / Deno `1.8.0-workspace-roles`. 기존 GAS v83 및 Handover·Drive 양식은 유지한다.

## 첫 화면

- 관리자는 `확인할 업무 / 전체 기간`, 현장 담당자는 `내 업무 / 이번 주`로 시작한다. 확인할 업무는 미배정(완료·취소 제외), 결과 확인 대기, 완료 후 원본 변경 확인을 포함한다.
- 전체 업무·내 업무·미배정·원본 변경으로 바로 전환할 수 있다. 업무 범위, 방문 기간, 상태를 서로 구분한다. 상단 상태 집계와 실제 목록은 동일한 역할·기간·검색 조건을 사용한다.
- 전체 기간의 원본 변경·결과 확인 안내는 접을 수 있는 `전체 확인사항`에 유지한다. 휴무 대상자는 상단에 표시한다.
- 처리 내역은 방문 일정 **내림차순**으로 시작한다. 일시가 없는 접수는 맨 뒤로 보낸다. 사용자가 정렬 기준과 방향을 변경할 수 있다.
- 본인 담당자는 기존 알림 계정 연결 정보를 사용한다. 이름이 중복되거나 연결을 확인하지 못한 상태에서 임의로 담당자를 추정하지 않는다. 내 업무의 건수는 연결 전 `—`로 표시하고 설정 경로를 안내한다.
- 목록을 넓게 사용하고 상세는 native dialog로 연다. 키보드 초점을 창 안에 유지하고 Esc/닫기로 목록으로 돌아간다. 댓글 초안은 기존 보존 경로를 사용한다. 상세의 다음 작업 버튼은 하단에 고정한다.

## 미배정 업무 가져오기와 일정 안내

- `내가 담당하기`는 서버가 인증된 계정의 담당자 연결을 다시 확인해 배정한다. 클라이언트가 제출한 담당자 이름으로 배정하지 않는다.
- 미배정 여부, 접수 버전, 담당자 연결을 재검증하고 원자적으로 저장한다. 동시 요청에서는 한 사람만 성공한다. 완료·취소·삭제 접수는 가져올 수 없다.
- 방문 일정이 겹치면 확인 후 재시도한다. 휴무는 최신 근무 일정을 읽어 안내하고 사용자가 확인 후 진행할 수 있다. 일반 접수 등록/수정 화면에도 휴무·동일 일시 안내를 제공한다.
- 가져오기는 기존 상태·방문일·메모·Handover 이력을 유지한다. 기존 배정 변경 알림과 변경 이력을 사용한다. 저장 응답 유실 시 동일 작업 ID로 재시도한다.

## 알림 읽음

- 알림 창의 `새로고침` 옆에 `선택 읽음`, `모두 읽음`을 배치했다. 각 병원 옆 선택란과 불러온 안 읽은 알림 전체 선택을 제공한다. 도구와 닫기 버튼은 목록을 스크롤해도 유지한다.
- 병원명 선택은 기존대로 해당 접수와 Handover를 최신 조회한 뒤 상세를 연다. 작성 중인 초안이 있으면 이를 보존한다.
- 직접 읽음 표시는 알림함만 정리한다. 접수 완료·Handover 원본 검토·PDF 비교 확인으로 처리하지 않는다. 기존 자동 열람 API의 최신 원본 확인 조건을 완화하지 않는다.
- 일괄 처리는 현재 계정의 알림만 50개씩 처리한다. 모두 읽음은 최근 30일의 다음 페이지도 포함한다. 작업 시작 후 새로 생성된 알림은 같은 작업에 포함하지 않는다. 중복 재시도는 새 처리 건수를 늘리지 않는다.
- 실패한 건은 다시 시도할 수 있고, 창 닫기/로그아웃 시 이어지는 배치를 멈춘다. 다른 계정의 늦은 응답은 화면에 반영하지 않는다. 읽은 알림의 대기 중 푸시 재시도는 중단한다. 이미 기기에 표시된 운영체제 알림을 회수하는 기능은 아니다.

## 검증

신규 `workspace-roles.mjs`: 담당자 위조·연결 변경·동시 가져오기·일정 충돌·상태/이력 보존·알림 소유권·전체 읽음 페이지·새 알림 제외·멱등성·읽은 알림 푸시 재시도 억제·역할/집계 일치.

기존 알림/인증/SW/알림 진입/집계/KV/조회 키/동선/원본 검토/중계/근무 일정/병원 업무 검증과 Deno 타입 검사 통과. 근무 일정 UI 하네스는 실제 필드 모듈과 현재 인증 인터페이스를 사용하도록 갱신했다.

Chrome 가상 데이터 검증: 관리자·담당자 기본 화면, 내림차순, 선택 2건과 전체 65건 처리, 병원 선택 후 최신 상세, 휴무 경고 후 가져오기, 긴 병원명, 댓글 초안 닫기/재열기, Esc, 모바일 알림 도구와 가로 넘침을 확인했다. 390px 화면 크기 설정은 실기기 터치·키보드·푸시 수신 시험과 구별한다. 운영 시트에 시험 접수나 댓글을 추가하지 않는다.
