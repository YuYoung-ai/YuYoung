# 앱 설치와 접수 알림

설치·알림 설정: https://yuyoung-ai.github.io/YuYoung/install.html

## 사용 순서

1. 설치 화면에서 안드로이드 또는 아이폰 안내를 확인한다.
2. Chrome 설치 메뉴 또는 Safari의 공유 → 홈 화면에 추가로 BAZ CS를 설치한다.
3. 설치한 앱에서 로그인하고 **접수 알림 받기**를 누른다.
4. 기기의 알림 권한을 허용하고 **테스트 알림 보내기**로 수신을 확인한다.
5. 업무 화면의 **알림**에서 최근 30일 알림을 다시 확인할 수 있다.

아이폰은 iOS 16.4 이상에서 홈 화면 앱으로 실행해야 한다. 앱 설치와 알림 권한은 별도다. 카카오톡 내부 브라우저에서는 설치 주소를 복사해 Chrome 또는 Safari로 열도록 안내한다. 알림을 거절했다면 기기 설정에서 허용한 뒤 다시 연결한다.

## 발송 조건

- 담당자를 지정한 신규 접수: 해당 담당자 계정에 발송한다.
- 담당자 미지정 신규 접수: **업무 조회 권한이 있는 전체 계정**에 알림 기록을 남기고, 알림을 연결한 기기로 푸시를 보낸다.
- 최초 배정·담당자 변경: 새 담당자에게 발송한다. 미지정으로 변경하면 전체 알림 대상이다.
- 내용 수정, 댓글, 상태 변경, Handover 동기화: 새 접수 알림을 반복하지 않는다.
- Flow 가져오기와 과거 자료 이전: 과거 접수 알림을 일괄 생성하지 않는다.
- 같은 저장 작업의 재시도: 같은 알림 이벤트를 재사용한다.

발송 직전에 현재 배정과 접수 상태를 확인한다. 배정이 바뀌거나 삭제·취소·완료되어 불필요해진 대기 작업은 발송하지 않는다. 이미 전달된 알림은 접수의 현재 상태를 조회해 확인한다.

## 계정 연결

알림 구독은 서버에서 인증한 계정 ID에 연결하며, 기존 로그인과 GAS HMAC 토큰 규칙을 유지한다. 새 로그인 토큰에는 추가 계정 식별자만 포함한다. 구형 토큰에서 이름이 여러 계정과 겹치면 알림 설정을 위해 다시 로그인하도록 안내한다.

업무 담당자 목록과 계정 이름이 유일하게 일치하면 자동 연결한다. 이름이 다르거나 중복되면 관리자가 설치 화면의 **계정과 업무 담당자 연결**에서 지정한다. Google 계정과 비밀번호 계정이 같은 이름으로 존재하는 경우도 여기서 각각 연결할 수 있다. 담당 업무를 연결하지 않아도 전체 알림은 받는다.

한 계정은 최대 10개 기기를 연결한다. 같은 브라우저의 구독은 한 계정에만 속한다. 로그아웃 시 서비스워커가 연결 표시를 지우고 브라우저 구독을 해제한다. 계정 전환 후에도 이전 계정의 발송 작업이 새 계정 기기로 전달되지 않도록 구독 소유자와 연결 버전을 검사한다.

## 알림에서 접수 열기

알림 주소는 `hospital-work.html?request=<접수 ID>&notification=<알림 ID>`다. 로그인 만료 시 대상 경로를 최대 30분 보존하고 로그인 후 원래 접수로 돌아온다. 복귀 경로는 같은 사이트의 업무 화면과 설치 화면으로 제한한다.

알림에서 진입하면 해당 접수에 연결된 Handover 기록 ID와 병원·방문일 후보만 갱신한다. Deno의 현재 접수와 이력을 기준으로 범위를 정하므로 Sheets의 접수 복제 지연에 의존하지 않는다. 기록 ID를 따라 병원명·처리일이 바뀐 원본도 조회한다. 연결된 원본이 사라졌거나 갱신이 실패하면 최신 확인 성공으로 표시하지 않는다.

이후 목록 변경분과 최신 상세를 조회한다. 성공한 상세의 리비전과 Handover 확인 시각으로 열람을 기록한다. 열람 기록은 접수 상태를 변경하지 않는다. 기존 Handover 연결에 따른 업무 상태 처리 규칙은 유지한다.

이미 열려 있는 업무 창은 새로고침 대신 알림 대상을 전달받는다. 작성창·댓글·저장 대기가 있으면 입력을 유지하고 **알림 접수 열기 / 다시 확인**을 표시한다. 오프라인·동기화 오류·삭제된 접수는 실패 상태와 재시도 안내를 표시한다.

## 서버 저장과 운영

알림 이벤트와 대기 작업은 접수 저장의 기존 KV 원자적 트랜잭션에 함께 기록한다. 기존 Sheets 복제 `outbox`와 알림 큐는 분리한다. 발송 실패가 접수 저장 성공을 취소하지 않는다.

저장 직후 제한된 즉시 발송을 시도하고, Deno Cron이 매분 남은 작업을 처리한다. 기기별 작업을 잠금으로 보호하고 일시적인 연결 오류·429·5xx는 지연을 늘려 재시도한다. 만료된 404/410 구독은 정리한다. 푸시는 최선의 전달 방식이며, 휴대폰 설정·회선에 따라 지연되거나 놓칠 수 있다. 발송 성공과 사용자 열람은 별도다.

- 알림 목록·열람·이벤트: 생성일 기준 30일.
- 푸시 전달 대기: 생성 후 최대 24시간, 재시도 횟수 제한 적용.
- 기기 구독: 마지막 연결 갱신 후 90일. 앱 접속 시 연결 갱신.
- VAPID 키: 서버가 WebCrypto로 최초 1회 생성하여 보호된 KV 영역에 보관. 공개 키만 인증된 설정 API로 반환한다. 인증 토큰·기존 계정·서명 비밀키를 교체하지 않는다.
- 사진·PDF: 기존 저장·공유 경로 유지. 알림에는 접수 ID와 짧은 제목·방문 안내만 담는다.
- 영구 삭제: 해당 접수의 알림 이벤트·목록·열람·발송 대기도 기존 재시도 가능한 삭제 정리에 포함한다.

앱 버전은 `baz-cs-v241`이다. 기존 설치 앱의 시작 주소와 앱 정체성을 유지한다. 서비스워커 갱신 시 알림 연결 표시 캐시는 보존하고, 로그아웃 시 지운다. 브라우저 구독 API에는 지원하는 푸시 제공자의 HTTPS 주소만 허용한다.

## 배포와 검증

GAS의 `hospital_work_gas.gs`, `hospital_work_kv_gas.gs`를 기존 프로젝트·배포에 반영한다. `Code.gs`, 권한 설정, 원본 시트는 변경하지 않는다. Deno는 새 main 빌드를 검증한 뒤 기존 운영 타임라인으로 승격하고 Cron 등록을 확인한다.

자동 검증:

- `test/work-notifications.mjs`: 전체 알림 ACL, 배정·변경, 중복 방지, 발송 재시도와 구독 만료, 계정 전환, 열람 조건, 보관 기간.
- `test/work-notification-sw.mjs`: 수신 계정 확인, 로그아웃, 기존 창 재사용, 주소 검증, 앱 갱신.
- `test/work-notification-auth.mjs`: 로그인 후 접수 복귀와 외부 주소 차단.
- `deno task check`, `deno task test:push`: Deno 타입 검사와 실제 npm/WebCrypto 암호화·복호화 검증. 암호화 테스트에서는 외부 기기에 알림을 보내지 않는다.
- 기존 KV·Handover·PDF·필터·인증 회귀 검증.

Chrome에서는 기기별 안내, 모바일 폭, 알림 목록, 알림 선택 후 Handover 수정 반영을 검증한다. **안드로이드와 아이폰에서 실제 설치 후 앱을 닫은 상태의 수신·선택은 각 기기에서 테스트 알림으로 최종 확인해야 한다.** Chrome의 화면 폭 검증을 아이폰 실기기 푸시 검증으로 간주하지 않는다.
