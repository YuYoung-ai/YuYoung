# 처리 내역 표시

- 상태는 접수(파랑), 방문예정(보라), 처리중(주황), 결과확인(청록), 완료(초록), 보류(노랑), 취소(회색)로 구분한다. 텍스트도 유지하며 밝은/어두운 테마를 지원한다.
- 상태 옆 AS 유/무상은 접수의 serviceOverrides.asType을 우선하고, 없으면 기존 병원 기준 조회 규칙을 사용한다. 미확인/미기록을 유상이나 무상으로 추정하지 않는다.
- CS 담당 표기를 CS 접수로 바꾸고 옆에 영업 담당자를 표시한다. 접수의 영업 담당을 우선하며 비어 있으면 연결된 병원 DB 값을 표시한다.
- 최근 기록은 삭제되지 않은 댓글의 최신 inspection_pdf를 새 탭 링크로 표시한다. 일반 댓글이 나중에 추가되어도 내역서 링크는 유지하며, 첨부가 없으면 대시로 표시한다. 재생성/삭제/복원은 접수 버전 변경 후 반영한다.
- 목록은 먼저 그린다. 표시된 최대 50건의 첨부 메타데이터만 250ms 지연 후 한 API로 조회한다. 같은 접수 버전의 결과는 브라우저 IndexedDB에 최대 300건 보관한다. 검색/정렬 시 기존 결과를 재사용하고 댓글 본문/감사 이력/파일 본문은 내려받지 않는다.
- work_inspection_links는 기존 업무 접근 권한을 검사한다. 최초 조회 때 해당 접수의 댓글만 읽고, 이후에는 접수 버전에 묶인 파생 KV 요약을 재사용한다. 동시에 최대 4건을 준비하고 7일 TTL로 보관한다. 영구 삭제는 요약도 정리하며 파일은 기존 Drive 권한으로 연다.
- 이전 PC 목록은 기존 수동 동기화 정책을 유지한다. 최초 메타데이터 조회에 실패하면 내역서 다시 확인 버튼을 표시한다.

검증: work-inspection-links.mjs, work-inspection-list.cjs, work-list-render.cjs, work-ui-cache.mjs, work-kv.mjs, work-pdf-attachments.mjs. KV 검사는 메모리 모델을 사용하며 실제 Deno KV 배포 검증과 구분한다.
