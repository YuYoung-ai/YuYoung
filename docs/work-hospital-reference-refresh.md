# 접수등록 병원DB 최신 확인

접수등록과 목록의 병원 검색은 업무용 참조 목록을 사용한다. 기존에는 이 PC의 목록을 복원하면 새 원본 DB 확인을 하지 않았고, 백그라운드 Handover 작업의 앞 단계에서 오류가 발생하면 참조 갱신도 지연될 수 있었다.

페이지 시작, 접수등록 열기, 병원 검색창 진입 시 기존 인증 API `work_references_refresh`로 Handover와 같은 원본 `hospdbrich`를 확인한다. 여러 진입은 진행 중인 요청 하나를 공유하며, 성공 후 5분 동안 다시 읽지 않는다. 실패하면 기존 목록을 보관하고 30초 동안 자동 재시도를 쉬며 수동 새로고침은 바로 재시도할 수 있다. 상태는 접수등록 창에 표시한다.

검색어·증상·입력 중인 담당자·초안은 유지한다. 이미 선택한 병원은 기존 병원 키/이름·지역·장비 판별 규칙으로 재연결한다. S/N이 비어 있는 병원도 원본 DB의 정상 행이면 검색·선택 가능하다. Flow에서 이전된 이력용 병원은 새 접수 선택 대상에서 제외하는 기존 정책을 유지한다. 일반 업무 동기화는 원본 DB 확인이 끝난 뒤 진행해 이전 참조 응답이 최신 목록을 덮지 않도록 한다.

이 변경은 기존 인증 경로와 운영 서버의 원본 DB 새로고침 기능을 사용한다. GAS·업무 백엔드 런타임이나 접근 권한을 변경하지 않는다. 원본 목록 갱신으로 기존 접수·처리 결과를 일괄 수정하지 않는다.

검증: `node test/work-hospital-reference-refresh.mjs` — 최초 진입/검색의 요청 중복 방지, 최신 확인 유효시간, 실패 보관/재시도, S/N 미기록 검색, 입력 보존, 동기화 순서 및 문법.
