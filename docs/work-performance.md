# 조회·사진·PDF 성능 개선 (웹 v245 / Deno 1.7.0)

접수 저장 시 전체 접수를 읽던 중복·일정 충돌 검사를 관련 병원과 담당자 일정 조회로 줄인다. PDF 도구는 생성 시 불러오며, 사진을 다시 화면으로 캡처하지 않고 원래 비율로 PDF에 배치한다. Handover 고정 기록 ID, 원본 지문 검증과 업로드 재시도 규칙을 유지한다.

## 조회 정합성과 배포

- `hospitalwork-v2/queryIndex` 아래 병원·담당자/방문시각·병원명/방문일별 ID 조회 키를 추가한다. 값에는 `{id}`만 저장한다. 이력 본문·사진·PDF를 복제하지 않는다.
- 접수와 조회 키, 준비 상태의 변경 순번을 하나의 원자적 저장으로 갱신한다. 완료·취소·삭제·복원·일정 변경도 포함한다. Handover의 방문 중복 판단에는 완료 접수도 남긴다.
- 기존 접수는 32건씩, 호출당 최대 4배치로 준비한다. 원본과 커서 버전을 확인하므로 동시 변경 시 같은 배치부터 재시도한다. 준비 완료 전에는 기존 전체 조회로 중복 누락을 막는다.
- 기존 매분 알림 Cron에서 알림 처리 후 준비 작업을 실행한다. 접수 화면도 인증된 `work_index_prepare` 호출로 배치를 이어간다. 실패 시 다음 조회/주기에 재개한다.
- 준비된 키를 읽을 때 현재 원본과 키를 재검증한다. 이전 버전으로 되돌린 동안 접수가 변경되면 메타 순번 불일치를 감지해 전체 조회와 재준비로 전환한다. 기존 KV 연결을 교체하지 않는다.
- 특정 접수의 Handover 원본을 갱신할 때도 관련 방문일만 검사한다. 전체 동기화의 전체 원본 점검 경로는 유지한다.

## PDF와 사진

- 기존 html2canvas 1.4.1 / jsPDF 2.5.1을 라이선스 주석과 함께 별도 파일로 옮겼다. 첫 생성 때 한 번 불러오고 버전 고정 파일은 캐시한다. 오프라인 첫 생성에는 해당 도구가 먼저 캐시되어 있어야 한다.
- 사진은 한 장씩 최대 긴 변 1600px, JPEG 0.8로 처리한다. 지원 기기는 Worker/OffscreenCanvas를 사용하고, 미지원·초기화 실패·처리 오류는 일반 캔버스로 재시도한다. 회전 정보를 적용하고 임시 비트맵·캔버스·URL을 정리한다.
- 세로 사진은 한 페이지, 가로·정사각 사진은 인접한 두 장까지 배치한다. 잘라내거나 가로로 늘리지 않는다. 순서·메모·사진 수를 보존한다.
- 본문은 기존 HTML 양식을 사용한다. 한 작업의 완전히 동일한 HTML만 인코딩된 본문 페이지로 재사용한다. 내용·서명·양식·생성 시각이 달라지면 다시 캡처한다. 작업 전환 시 캐시를 비운다. 20페이지 초과는 오류로 안내한다.
- 실제 PDF가 7MiB를 초과할 때만 사진 인코딩을 단계적으로 조정한다. 본문·사진을 임의로 생략하지 않는다. 계속 초과하면 기존 업로드 상한을 적용하고 생성 파일/작성 내용은 보존한다.
- 생성 중 재클릭과 작업 전환을 막고 생성 시작 시의 본문·사진·파일명·연결 정보를 사용한다. 처리 중 입력이 바뀌면 변경된 초안을 완료로 덮어쓰지 않는다.
- 생성 전 확인한 원본 ID·지문을 업로드에 재사용한다. GAS는 업로드 시 잠금 안에서 지문과 문서 버전을 다시 확인한다. 다른 PDF와 충돌하면 자동 반복 전송을 멈추고 재생성을 안내한다.

## 측정 결과와 범위

2026-10-15 Windows / Chrome 로컬 검증. 합성 데이터만 사용. 아래 시간은 운영망이나 Google Drive 업로드 시간을 보장하는 수치가 아니다.

| 접수 수 | 기존 검사 읽기 수 | 개선 읽기 수 | 기존 p95 | 개선 p95 |
|---|---:|---:|---:|---:|
| 100 | 107 | 10 | 2.99ms | 1.95ms |
| 1,000 | 1,007 | 10 | 15.88ms | 3.52ms |
| 10,000 | 10,007 | 10 | 124.61ms | 3.62ms |

같은 런타임의 실제 메모리 KV에서 5회 준비 후 20회 중복 검사. Google/인증/네트워크를 포함하지 않는다. 관련 후보가 많으면 그 후보 수에 따라 읽기가 증가한다.

Chrome에서 세로·가로·정사각·작은 라벨·화면 성격의 합성 사진 5장을 동일하게 사용했다. 기존 PDF 반복 생성 5회는 1.30~1.71초였다. 개선 후 첫 실행(도구 다운로드 포함)은 1.38초, 동일 본문 재생성 4회는 0.40~0.56초였다. 테스트용 원본/업로드 응답을 사용했고 실제 Drive 저장 시간은 포함하지 않았다.

사진을 더 크게 읽을 수 있게 세로 페이지를 분리해 샘플은 기존 약 1.05MB/4페이지에서 약 1.58MB/5페이지가 됐다. 모든 PDF가 더 작아지는 변경은 아니다. 초기 HTML은 약 697KB에서 약 131KB로 줄고 PDF 도구 약 567KB는 첫 생성 시 받는다(비압축 파일 기준).

`BazPerf`는 최근 200개 숫자 측정만 메모리에 보관한다. 화면/검색/사진/PDF/업무 API와 Server-Timing의 서버·Google 시간을 구분한다. 병원명·본문·사진·토큰을 수집하거나 외부에 전송하지 않는다.

## 검증과 남은 범위

- 신규 `work-indexes`, `inspection-performance`, `work-perf-metrics` 및 기존 KV/원본 검증/알림 인증/PDF 업로드·양식·파일명/동선/보안 테스트 통과.
- Chrome 실제 생성: 기본 양식의 CS 서명, 간소화 양식 제외 항목, 사진 5장 비율과 순서, Worker 미지원 대체 처리, EXIF 회전 사진 확인. Poppler로 생성 페이지를 렌더해 확인했다.
- 검색 가능한 한글 텍스트 PDF는 별도 로컬 시제품에서 추출/검색과 기본·간소화 영역 분리를 확인했다. 운영 브라우저의 폰트 포함, 긴 표와 줄바꿈, 서명 및 모바일 메모리 검증은 남아 있어 이번 배포는 기존 본문 양식을 유지한다. 시제품은 저장소/서버에 배포하지 않는다.
- Android/iPhone 실기기의 메모리·속도·카카오톡 공유와 실제 통신 속도는 실기기에서 별도 확인한다.

GAS 변경·재배포는 필요하지 않다. 운영 전환 후 Deno 버전, 기존 KV 연결, `queryIndexReady`, 알림 Cron 성공, 웹 v245를 확인한다.
