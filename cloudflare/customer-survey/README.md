# 병원 고객만족도 조사

고객 화면은 `customer-survey.html`, 로그인한 직원의 관리 화면은 `survey-admin.html`이다. 기존 `survey.html` A/S 평가와 점검 QR 서명 기능은 유지한다.

## 운영 순서

1. 관리자(레벨 2 이상)가 **조사 관리 → 초안 만들기**로 회차를 만든다.
2. 한국시간 시작/종료 일시와 제목을 설정하고 상태를 **접수 중**으로 저장한다. 한 번에 한 조사만 접수할 수 있다. 날짜를 비우면 시작/종료 제한이 없다.
3. 직원(레벨 1 이상)이 병원명을 선택하거나 입력하고 **QR · 링크 생성**을 누른다. 기존 로그인 토큰으로 병원 목록을 조회하며, 병원 목록 연결 실패 시 수동 입력이 가능하다.
4. 안내 문구/URL을 복사해 회사 문자 발송 수단으로 직접 보내거나 QR 이미지를 저장해 병원에 전달한다. 자동 문자 발송 기능은 없다. 실제 전달 후 **전달 완료 기록**을 누른다.
5. 고객은 로그인 없이 전용 QR/주소에서 8문항에 응답한다. 1~7번은 필수, 8번 자유 의견은 선택이다. 병원별 회차당 1회 응답한다.
6. 관리자는 **결과 통계**에서 회차·병원·응답 기간으로 조회하고 CSV를 내려받는다.

병원별 QR/주소는 다음 조사에도 재사용한다. 주소의 `#h=`에는 192비트 난수 코드만 넣고 병원명·직원 연락처·로그인 토큰은 넣지 않는다. QR은 로컬 인코더로 생성한다. 고객 화면에는 응답 여부만 반환하며 이전 답변은 공개하지 않는다. 링크를 가진 사람이 병원 대신 응답할 수 있으므로 링크는 해당 병원에 전달한다. 원장 본인 인증은 포함하지 않는다. 병원 링크 중지/재사용은 관리자만 가능하다.

## 통계

- 가격·품질·납기·서비스·사용 편의성의 5점 분포, 항목별 평균, 만족 이상(4~5점) 비율을 표시한다. 전체 만족도 점수는 만들지 않는다.
- 구입 동기는 복수 선택이며 분모는 응답 병원 수이다. 비율 합계는 100%를 넘을 수 있다.
- 응답률은 `전달 기록 중 조회 기간에 응답한 병원 / 해당 회차 전체 전달 병원`이다. 전달 기록 없는 응답도 문항 통계에 포함한다. 병원당 전달 이력은 회차별 1건으로 갱신한다.
- 응답은 페이지당 50건, 전달 현황은 최근 200곳을 표시한다. CSV는 필터 조건의 최대 1만 건을 내보내며 한글 BOM, 따옴표/줄바꿈, 수식 문자열 이스케이프를 처리한다. 제출시각은 한국시간이다.

## 저장·접근

기존 Cloudflare 계정의 별도 Worker `baz-customer-survey`와 별도 D1에 저장한다. 기존 인증 Worker의 `verify`를 호출하여 서버에서 권한을 검증한다. 직원용 데이터는 Bearer 토큰으로만 요청한다. 모든 API 응답은 `no-store`다. 연락처, 환자정보, IP, 기기 식별자는 수집하지 않는다. 의견 입력란에서 개인정보 작성을 피하도록 안내한다. 화면의 임시 응답은 같은 탭의 `sessionStorage`에만 보관하고 성공 시 제거한다.

회차를 만들 때 설문 정의 JSON(현재 `2026-10-v1`)을 저장해 고정한다. 향후 문항 변경은 `js/baz-survey-schema.mjs`를 수정하고 버전을 올린 뒤 **새 회차**를 만든다. 이미 생성한 회차의 문항/기존 응답은 바꾸지 않는다. 수집 데이터의 보관·삭제 정책은 실제 운영 방침에 맞춰 별도로 정한다. 이 초안에는 자동 삭제나 관리자 응답 수정 기능이 없다.

## 개발·배포

Node 24 이상에서 저장소 루트의 `node --test cloudflare/customer-survey/test/worker.test.mjs`로 테스트한다. 실제 고객 데이터 없이 메모리 SQLite로 D1의 JSON/중복 제약/기간/권한/통계를 검증한다.

이 폴더에서 Wrangler 4.151.3으로 `wrangler deploy --dry-run`, `wrangler d1 migrations apply baz-customer-survey --remote`, `wrangler deploy` 순서로 배포한다. 인증은 로컬 Wrangler 로그인으로만 관리하며 인증정보를 저장소에 넣지 않는다. 프런트는 GitHub Pages의 main 배포를 사용한다. 테스트 workflow는 서버 검증을 수행하며 Cloudflare를 자동 배포하지 않는다.

월 100응답 규모의 일반 사용을 전제로 한 초안이다. 서버 사용량은 Cloudflare의 해당 Worker와 D1 대시보드에서 확인한다. 문자 발송 비용은 별도 발송 수단의 요금에 따른다.
