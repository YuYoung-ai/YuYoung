# 병원 고객만족도 조사

## 역할별 화면

| 대상 | 화면 | 접속과 기능 |
| --- | --- | --- |
| CS 관리자 | survey-admin.html | 기존 앱의 관리자 레벨 2 이상. 조사 생성·문항 편집·기간·상태·결과·CSV·영업팀 비밀번호 설정 |
| 국내영업팀 | survey-sales.html | 기존 앱 로그인 없이 별도 공용 비밀번호. 병원별 QR·URL·문자 문구 생성과 실제 전달 기록만 사용 |
| 고객 | customer-survey.html#h=병원코드 | 로그인 없이 병원별 설문에 참여 |

CS 관리의 조사 관리 탭은 **새 조사 만들기**와 **접수 기간·상태**로 구분한다. QR·안내 문자 화면 오른쪽에는 만드는 방법과 사용하는 방법을 항상 표시한다. 넓은 화면에서는 안내가 스크롤을 따라가고 휴대폰에서는 아래에 배치한다.

## 조사 생성·문항 편집

1. 기본 8문항 또는 기존 회차의 문항 구성을 불러온다.
2. 제목·첫 화면 안내·질문·선택지·필수 여부·문항 순서를 편집한다. 단일 선택, 복수 선택, 5점 만족도, 서술형을 추가하거나 삭제할 수 있다.
3. 고객 설문 미리보기로 확인하고 **조사 초안 등록**을 누른다. 문항은 1~30개, 선택지는 2~12개, 서술형 상한은 최대 2,000자다.
4. 접수 기간·상태에서 기간과 상태를 저장한다. 동시에 한 조사만 접수한다. 날짜는 한국시간이며 빈 날짜는 제한이 없다.

등록 후 문항 수정은 **초안이며 응답이 없는 회차**에서만 가능하다. 접수 중이거나 응답이 있는 회차는 새 회차로 복사한다. 서버가 문항 식별자·타입·선택지와 수정 버전을 검사하고 조건부 UPDATE로 변경 경합을 차단한다. 회차별 문항 스냅샷은 기존 결과와 함께 유지한다.

기본 구성은 인지 경로 1문항, 구입 동기 복수 선택 1문항, 가격·품질·납기·서비스·편의성 5점 척도 5문항, 선택 자유 의견 1문항이다. 개인정보·휴대폰·경품 문항은 추가하지 않는다. 고객 화면은 따뜻한 배경, 흰색 카드, 코랄색 진행률, 질문 번호, 둥근 이동 버튼과 감사 안내를 사용한다.

## 영업팀 배포

CS 관리의 **영업팀 접속 설정**에서 제작자가 10~128자의 공용 비밀번호를 설정한 뒤 전용 페이지 URL과 함께 영업팀에 안내한다. 프로그램에는 운영 비밀번호를 미리 넣지 않는다. 공용 비밀번호 원문은 저장하거나 다시 표시하지 않는다.

비밀번호는 난수 salt와 PBKDF2-SHA256 100,000회로 해시한다. 로그인에는 Cloudflare Rate Limiting을 적용하고 세션은 8시간 만료다. 세션 토큰은 브라우저 sessionStorage에, 서버에는 토큰 해시만 저장한다. 비밀번호 변경, 접속 중지, 만료, 로그아웃 시 세션을 폐기한다. 영업팀 세션으로 CS 관리자 API나 결과 조회에 접근할 수 없다. 공유 비밀번호 방식은 개인별 작업자 식별을 제공하지 않는다.

영업팀과 CS의 QR 발급 목록은 제공된 입점병원 Excel의 지정 시트에서 병원명만 추출해 별도 D1 survey_directory에 가져온다. 동일 병원명은 하나로 합친다. 기존 업무 서버·GAS 병원 검색 DB는 조회하지 않으며, 과거 발급한 병원명도 검색 목록에 합치지 않는다. 서버와 화면 모두 목록에 있는 병원만 발급한다. 기존 QR·전달·응답 기록은 유지한다. 이름 목록과 원본 Excel은 공개 저장소에 포함하지 않고 별도 관리하며, 연락처·주소 등 다른 열과 다른 시트는 가져오지 않는다. 목록 교체는 해당 테이블만 트랜잭션으로 교체한 뒤 원본과 정확히 대조한다.

문자는 복사한 안내 문구를 회사의 발송 수단으로 직접 전달한다. 현장에서는 QR을 보여주거나 이미지로 저장해 출력한다. 실제 전달 뒤 전달 완료 기록을 남긴다. 회차당 같은 병원은 1곳으로 집계한다. 자동 문자 발송은 포함하지 않는다.

## 병원 QR 일괄 생성 · 스티커 제작

CS 관리자의 **QR 일괄 생성** 탭에서 입점병원을 검색하거나 전체 선택하고 병원별 제작 수량을 설정한다. 검색 결과 선택은 검색에 맞는 모든 페이지에 적용되며, 검색·페이지를 바꿔도 선택은 유지된다. 병원 목록은 50곳씩 표시한다.

선택한 병원의 QR은 기존 관리자 `hospital-save` API를 최대 3개 요청씩 사용해 준비한다. 이미 발급한 병원은 같은 고정 주소를 재사용하고, 조사 접수 전에도 발급할 수 있다. 중지된 링크는 출력 대상에 넣지 않는다. 완료 결과는 일부 요청이 실패해도 유지되며 실패 항목 재시도와 생성 중지를 지원한다. 중지할 때는 진행 중인 요청까지만 마친다. 로그인·권한 오류가 나면 새 요청을 중단한다. 병원명과 결과는 브라우저 세션의 화면 메모리에만 보관하며, 새로고침 후 재생성해도 서버의 기존 병원 주소는 유지된다.

- **스티커 PDF:** 가로 32 × 세로 25mm, 병원당 한 페이지. QR은 왼쪽, 병원명·안내는 오른쪽, 하단 `Curejet`은 가운데 정렬한다. QR은 벡터이고 사방 4모듈의 흰 여백을 확보한다. 한글은 번들 Pretendard 글꼴로 약 600dpi 이미지를 만들며, Curejet은 PDF 기본 글꼴로 출력한다. 완성 크기의 흰 바탕 PDF이므로 업체의 도련·재단선·색상 규격은 인쇄 전 확인한다.
- **QR 이미지 묶음 ZIP:** 병원별 1024px PNG와 벡터 SVG, 제작 수량표 CSV, 인쇄 요청사항을 포함한다. QR 자체만 포함하는 이미지이며 스티커 완성 디자인은 PDF로 받는다.
- **제작 수량표 CSV:** PDF 페이지 번호·병원명·인쇄 병원명·병원 관리번호·수량·참여 주소·QR 파일명을 담는다. UTF-8 BOM과 수식 문자열 보호를 적용한다.

선택한 병원의 QR이 모두 준비된 경우에만 파일을 저장할 수 있다. 실패 항목을 제외하려면 **생성 완료 병원만 선택**을 누른다. 작은 스티커에 병원명이 들어가지 않으면 미리보기의 **인쇄 병원명**을 줄인다. 병원명 표시만 바뀌며 QR의 병원 연결은 유지된다. PDF 출력 매수는 페이지 복제가 아니라 수량표로 지정한다. 파일 생성·다운로드는 전달 기록이나 응답률에 영향을 주지 않는다. 실제 전달 후 기존 **QR · 안내 문자** 메뉴에서 전달 완료를 기록한다.

본 제작 전 실제 크기 100% 샘플로 QR 인식·병원명·하단 문구·재단 위치를 확인한다. 인쇄 산출물과 실제 병원 명단은 공개 저장소에 커밋하지 않는다. 이 기능은 기존 관리자 API와 번들 QR/ZIP/PDF 도구를 이용하므로 별도의 Worker 배포나 DB 변경이 필요하지 않다.

## 고객·통계

문자·QR은 `https://curejet.coaptation.workers.dev/병원별난수` 형태의 큐어젯 전용 참여 주소로 생성한다. 화면에는 긴 URL 대신 **고객만족도 조사 참여하기** 링크를 표시한다. 문자에는 참여 안내와 짧은 주소가 포함된다. 병원명을 수정하면 이전 QR·문구가 숨겨지고 다시 생성하도록 한다. 주소의 22자 URL-safe 코드는 128비트 난수이며 병원명·연락처를 포함하지 않는다. 별도 경량 Worker가 서비스 바인딩으로 설문 서버를 조회해 고객 설문으로 연결한다. 병원 링크가 중지되면 연결도 차단된다. 병원별 QR/주소는 다음 회차에도 재사용한다. 주소에는 난수 코드만 포함하고 직원 연락처·로그인 토큰을 넣지 않는다. QR은 브라우저에서 생성한다. 고객에게는 현재 병원·설문·응답 여부만 반환하며 이전 답변은 공개하지 않는다. 원장 본인 인증은 포함하지 않는다. 해당 병원에 전달한 링크로 병원별 회차당 1회 참여한다.

고객 문항, 문항 수·예상 시간, 필수 검사, 결과 차트, 원문 응답과 CSV는 회차의 문항 정의에 맞춰 표시한다. 선택 문항은 해당 문항에 응답한 병원 수를 분모로 집계한다. 복수 선택 비율의 합은 100%를 넘을 수 있다. 5점 문항은 개별 분포·평균·4~5점 비율을 제공하며 종합 점수는 만들지 않는다.

응답률은 전달 기록 중 조회 기간 응답 병원 / 해당 회차 전체 전달 병원이다. 전달 기록 없는 응답도 문항 통계에는 포함한다. 결과 화면은 남색 사이드바, 네 개의 집계 카드, 항목별 평균·분포, 선택형 통계와 서술형 의견 카드로 구성한다. 병원별 개별 답변 표는 표시하지 않는다. 배포·응답·응답률·개선 의견 카드를 누르면 CS 전용 상세 목록이 열린다. 병원 목록은 50곳씩, 개선 의견 본문은 4건씩, 의견 상세는 20건씩 전체를 페이지로 조회한다. 병원명·의견 검색과 의견 최신순·오래된순 정렬을 지원한다. 개선 의견 수는 비어 있지 않은 서술형 답변 건수이며, 서술형이 여러 문항이면 각 답변을 한 건으로 센다. 전달 이력은 반복 기록을 모두 보존하고 상세 목록에서 날짜·방식·참여 여부와 응답 일시를 확인한다. 기존 저장 자료에서는 마지막 전달 기록만 이관하며 과거에 덮어쓴 기록은 복원하지 않는다. 배포 수는 반복 전달해도 병원당 한 곳으로 센다. 조회 기간 밖에 응답한 병원은 별도로 표시하고 응답률 분자에서 제외한다. 집계 응답에는 개별 선택 답변을 싣지 않으며 CSV는 필터 조건의 최대 1만 건이다. CSV는 한국시간, 한글 BOM, 줄바꿈·따옴표와 수식 문자열 보호를 적용한다.

## 저장·운영

기존 인증 Worker는 유지하고, 별도 Worker baz-customer-survey와 별도 D1에 저장한다. API 응답은 no-store다. 요청 본문은 로그에 남기지 않으며 의견에 환자정보나 개인 연락처를 적지 않도록 안내한다. 접속 횟수 제한에 사용하는 네트워크 주소의 해시는 Rate Limiting 키로만 사용하고 설문 DB에는 저장하지 않는다. 자료 보관·삭제 기간은 회사 운영 방침에 맞춰 별도로 정한다.

## 개발·배포

Node 24 이상에서 저장소 루트의 `node --test cloudflare/customer-survey/test/*.test.mjs`로 43개 검증을 실행한다. 메모리 SQLite로 문항·권한·회차·중복·집계·CSV·공용 비밀번호·세션·영업팀 권한 분리를 검사한다. 프런트는 브라우저에서 따로 검증한다.

Wrangler 4.151.3으로 이 폴더에서 `wrangler deploy --dry-run`, `wrangler d1 migrations apply baz-customer-survey --remote`, `wrangler deploy` 순으로 배포한다. 인증정보는 저장소에 넣지 않는다. 프런트는 GitHub Pages main 배포를 사용한다. 테스트 workflow는 Cloudflare 배포를 자동 실행하지 않는다.
